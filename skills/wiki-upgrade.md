Upgrade the cc-tools managed section in this wiki's CLAUDE.md: $ARGUMENTS

Run from the wiki root (the directory containing CLAUDE.md).

## Step 1 — Verify sentinels

Check that CLAUDE.md contains both sentinel markers. If either is missing, the file
was not initialised from the template and cannot be upgraded automatically — report
this and stop.

```bash
grep -c "cc-tools:wiki:begin\|cc-tools:wiki:end" CLAUDE.md
```

The output should be `2`. If not, stop and explain.

## Step 2 — Apply the upgrade

Replace the content between the sentinels with the current wiki-schema.md from cc-tools:

```bash
WIKI_CLAUDE="CLAUDE.md"
SCHEMA=$CC_TOOLS/templates/wiki-schema.md

WIKI_CLAUDE="$WIKI_CLAUDE" SCHEMA="$SCHEMA" python3 - <<'PYEOF'
import os, re, pathlib
path   = pathlib.Path(os.environ["WIKI_CLAUDE"])
schema = pathlib.Path(os.environ["SCHEMA"]).read_text()
text   = path.read_text()
begin  = "<!-- cc-tools:wiki:begin -->"
end    = "<!-- cc-tools:wiki:end -->"
block  = begin + "\n" + schema.strip() + "\n" + end
result = re.sub(
    re.escape(begin) + r".*?" + re.escape(end),
    lambda m: block,
    text,
    flags=re.DOTALL,
)
path.write_text(result)
PYEOF
```

## Step 3 — Inject Session Start placeholder if missing

Check whether CLAUDE.md already has a Session Start section:

```bash
grep -c "## Session Start" CLAUDE.md
```

If the output is `0`, inject the placeholder before the managed block:

```bash
WIKI_CLAUDE="CLAUDE.md" python3 - <<'PYEOF'
import os, pathlib

path = pathlib.Path(os.environ["WIKI_CLAUDE"])
text = path.read_text()

if "## Session Start" in text:
    print("Session Start section already present — skipping.")
else:
    placeholder = """\
## Session Start

**Before responding to any user request, read these documents:**

<!-- List the authoritative live-state documents for this wiki. The goal: Claude reads
current project state rather than working from training priors or session memory.
Typical entries for a research-manager wiki:

1. `hypotheses/<slug>.md` — current claim state, confidence levels, retractions
2. `<subwiki>/syntheses/verdict-registry.md` — what papers support which claims
3. `log.md` — most recent entry, to know where the last session left off

Update this list as the wiki evolves. It typically changes 2-4 times over a long
project, at phase transitions - not every session. -->

1. `log.md` — check the most recent entry before starting work

**Why:** This wiki accumulates project-specific claim structure that does not exist in
Claude's training data. Working from memory substitutes training priors for the evolved
project understanding. Native knowledge is not a substitute for reading the current state.

**ORIENTATION.md:** When present, read it first — it is a one-page current-state summary
regenerated by `/wiki-orient`. If absent, read the documents listed above directly.

"""
    sentinel = "<!-- cc-tools:wiki:begin -->"
    text = text.replace(sentinel, placeholder + sentinel, 1)
    path.write_text(text)
    print("Session Start placeholder injected.")
PYEOF
```

Report whether the section was injected or already present.

## Step 4 — Verify and report

Read CLAUDE.md and confirm:
- The Sub-wikis table is unchanged
- The managed section (Structure, Page conventions, workflows, tools) reflects the
  current cc-tools template

Append to `log.md`:
```
## [<YYYY-MM-DD>] upgrade | cc-tools wiki schema updated
```

## Step 5 — Update project settings

Run:

```bash
bash $CC_TOOLS/setup-claude.sh --project .
```

This merges any new standard allowlist entries into `.claude/settings.local.json`
so that newly added tools (e.g. `curl`, `mkdir`) do not trigger permission prompts
after a cc-tools update. Safe to run — never removes existing entries.
