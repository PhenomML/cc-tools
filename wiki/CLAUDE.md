# cc-tools Wiki

**Driving question:** What are we learning about AI-assisted research tooling through building and using cc-tools?

This wiki is a living artifact — both working memory for the cc-tools Claude and a demonstration for adopters of how cc-tools can be used to document its own evolution. Read it as evidence of the self-improvement loop in practice.

## Session Start

1. Read `ORIENTATION.md` at the repo root for current codebase state
2. Read `wiki/log.md` for what changed in recent sessions
3. Read any wiki pages relevant to today's work before starting

## Session End

1. Update `wiki/log.md` with a brief entry: what changed, what's pending
2. If factual knowledge was generated (tool behavior, patterns, upstream findings), write or update the relevant wiki page
3. If private memory files were updated, check whether the content belongs here instead (or as well)

## Structure

| Directory | Purpose |
|---|---|
| `wiki/tools/` | Per-tool documentation as lived experience — behavior, failure modes, upstream status |
| `wiki/patterns/` | Design patterns discovered through building and using cc-tools |
| `wiki/upstream/` | External relationships — Michal/make4ht, planned outreach, community engagement |

## What belongs here vs. private memory

**Wiki (this directory):** Factual knowledge useful to both human and AI — tool behavior, design decisions, upstream relationships, patterns that emerged from use. Audience: Andrew, future Claudes, cc-tools adopters.

**Private memory (`~/.claude/projects/.../memory/`):** Behavioral corrections, session-navigation pointers, project state that is too operational or too personal for public documentation.

When in doubt: if Andrew would find it useful to read, it belongs in the wiki.

## For cc-tools adopters

The session history, tool assessments, and patterns in this wiki were generated by the same tools documented in `claude-md-section.md`. The wiki is the record of cc-tools being used to build cc-tools — a demonstration of the self-improvement loop this toolset makes possible.
